# FlowCost 0.5.3 — доступы и присутствие

## Почему синхронизация выглядела как личная

До 0.5.3 при регистрации создавались копии стартового процесса с независимыми `process_id`. В 0.5.3 регистрация больше не создаёт сценарии, а миграция удаляет старый публичный пример и только неизменённые копии, автоматически созданные из него. Права на открытие процесса определяются его владельцем, списком `process_shares` и значением `visibility` (`private`/`public`).

## Как сейчас организован доступ

- Процесс с видимостью `public`, созданный пользователем, доступен всем зарегистрированным аккаунтам только для просмотра, если владелец отдельно не выдал право редактирования.
- Личный процесс принадлежит создавшему его пользователю.
- Владелец может выдать другому зарегистрированному пользователю права `view` или `edit` через меню «Совместная работа».
- Пользователь без доступа может запросить его со страницы `/team/online` либо открыв прямую ссылку на закрытый процесс.
- Владелец видит ожидающие запросы на `/team/online` и может разрешить редактирование, просмотр или отклонить запрос.
- После одобрения оба пользователя открывают один URL `/processes/<process_id>`; общий журнал и WebSocket-комната относятся к одному ID.

## Онлайн-список

Каждая вкладка отправляет heartbeat раз в 10 секунд. Сервер считает вкладку активной в течение 45 секунд после последнего heartbeat. `/api/presence/online` группирует активные вкладки по пользователю и показывает процессы, которые они редактируют. Название процесса, к которому нет доступа, не раскрывается. Обновление UI выполняется каждые 5 секунд.

Курсоры и изменения графа по-прежнему идут через WebSocket текущего процесса. Для локальной разработки это рассчитано на один экземпляр backend; несколько процессов/серверов требуют внешнего брокера для комнаты WebSocket и общего presence-хранилища.

## API и поведение в 0.5.3

- `POST /api/presence/heartbeat` — зарегистрировать/обновить активность вкладки или удалить её при выходе.
- `GET /api/presence/online` — список активных аккаунтов с доступными/закрытыми активными процессами.
- `POST /api/processes/{id}/access-request` — отправить владельцу запрос на редактирование.
- `GET /api/access-requests/incoming` — запросы к процессам текущего пользователя.
- `POST /api/processes/{id}/access-requests/{requester_id}/decision` — одобрить или отклонить запрос; при одобрении выбирается `edit` или `view`.

## Ограничения

Presence — polling, не отдельный глобальный WebSocket. При закрытии браузера запись может оставаться видна до 45 секунд. Общая база ресурсов и один локальный backend сохраняются от предыдущей версии; перед размещением в сети организации нужна изоляция рабочих пространств и защищённое HTTPS/WSS-развёртывание.
