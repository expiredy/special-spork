# FlowCost 0.5.1 — совместная работа, курсоры и структура проекта

## Что ломало синхронизацию

Во время разбиения монолитного backend persistence-код был вынесен в `services/collaboration_store.py`. При сохранении операции время обновления должно браться через `now_iso()`, но зависимость не была передана в модуль. В результате каждая настоящая операция графа (например, `position.x` или `node.remove`) могла завершаться внутренней ошибкой до commit SQLite. В браузере соединение закрывалось, а другие участники не получали подтверждённый снимок. Это объясняет, почему одно лишь установление WebSocket-соединения не гарантировало работу синхронизации.

Исправление: `now_iso_fn` передаётся из composition root в `commit_collaboration_operation_batch()` и `persist_collaboration_state()`. Канонический граф, revision, idempotency receipt и запись `process_events` коммитятся в одной транзакции. Интеграционный smoke-тест теперь отправляет изменение позиции и удаление узла через настоящий WebSocket между двумя зарегистрированными пользователями и проверяет подтверждение, рассылку снимка и сохранение в SQLite.

## Курсоры и диагностика

- Frontend отправляет нормализованные координаты курсора по WebSocket после присоединения к процессу.
- Backend транслирует cursor/presence только другим подключённым участникам той же комнаты.
- На frontend сообщения `cursor` принимаются только от другого `client_id`, отображаются поверх canvas и автоматически очищаются после паузы.
- Если пакет не получил ACK за 8 секунд, приложение сообщает об этом и инициирует переподключение с проверкой серверного состояния.
- Ошибки WebSocket со стороны backend попадают в backend log и по возможности возвращаются клиенту как `error`, вместо молчаливого закрытия.

Smoke-тест подтверждает передачу курсора между двумя WebSocket-клиентами. Он тестирует backend transport, а не пиксельную отрисовку браузерного курсора; визуальную проверку стоит выполнить в двух окнах после локального запуска frontend.

## Прямые URL

- `/processes/:id` — холст процесса;
- `/processes/:id/activity` — журнал событий;
- `/processes/:id/estimate` — смета;
- `/processes/:id/settings` — настройки процесса;
- `/processes/:id/responsibility` — представление дорожек ответственности;
- `/team` — сотрудники, роли и грейды;
- `/team/tools` — каталог инструментов;
- `/team/financial-goals` — финансовые цели.

URL parsing/generation находится в `frontend/src/lib/routes.js`; direct-route тесты — в `frontend/tests/collaboration.test.mjs`.

## Условия, важные для работы двух браузеров

Оба браузера должны открывать **один и тот же backend** и один и тот же процесс. Если второй участник подключается с другого компьютера, `localhost` в его браузере указывает на его собственный компьютер. Задайте единый `VITE_API_URL`, разрешите origin frontend-сервера в `FLOWCOST_ALLOWED_ORIGINS` и запускайте backend с одним Uvicorn worker: список WebSocket-комнат и курсоров пока хранится в памяти одного процесса. Также владелец процесса должен выдать второму пользователю доступ как минимум на просмотр; для перемещения/удаления нужен доступ на редактирование.
